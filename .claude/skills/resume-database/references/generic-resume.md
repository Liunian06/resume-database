# 通用简历生成

## 触发场景

当候选人初始化Skill、整理完CV后，**还没有明确的目标岗位**时，生成一份通用简历供候选人日常使用或快速投递。

**典型场景：**
- 用户刚导入零散材料，整理完CV，暂时没有具体投递计划
- 用户需要一份"拿得出手"的简历参加招聘会或内推
- 用户想先看看自己的经历整理成简历是什么样子

**与定向简历的区别：**
- 通用简历：无特定岗位，按经历亮眼程度排序，全面展示候选人能力
- 定向简历：针对特定岗位，按与JD匹配度排序，突出相关经历

## 输入内容

### 必读
- `cv_CN.md`或`cv_EN.md` - 候选人事实库

### 不读取
- 不读取JD、岗位画像、企业背调
- 通用简历不针对特定岗位

## 简历结构

### 固定顺序部分
1. **个人信息** - 姓名、学校、专业、联系方式
2. **教育经历** - 学校、学历、专业、时间、GPA、核心课程

### 动态排序部分（按亮眼程度排序）

从CV中所有经历板块中选取，**按以下标准评估亮眼程度，从高到低排序**：

**亮眼程度评估标准（优先级从高到低）：**
1. **大厂实习/知名企业实习** > 小公司实习 > 校内项目
2. **有量化成果的经历** > 无量化成果的经历
3. **时间较长的经历**（3个月以上）> 短期经历
4. **近期经历**（1年内）> 较早经历
5. **技术含量高/复杂度高的经历** > 简单经历
6. **获得认可的经历**（如获奖、被采纳、有正反馈）> 无认可的经历

**可能的经历板块：**
- 实习经历
- 项目经历
- 科研经历
- 比赛经历
- 校园经历

**排序策略：**
1. 对CV中每段经历按上述6条标准打分
2. 将最亮眼的经历所在板块放在教育经历之后
3. 依次排列其他板块，亮眼程度递减
4. 同一板块内的多段经历也按亮眼程度排序
5. 如某板块的所有经历都不够亮眼（如都是校内简单项目），可以省略或放在最后

**技能与证书板块位置：**
- 一般放在所有经历板块之后
- 如候选人技能特别突出（如掌握稀缺技术栈、有权威证书），可以提前到教育经历之后

**个人优势板块：**
- 放在最后，用2-3条概括候选人最亮眼的优势，每条要有经历或数据支撑
- 含金量高的奖项（国家级、省级、知名竞赛）写进教育经历的"获奖情况"或比赛经历；普通奖项可省略

## Bullet改写规则

### STAR法则
通用简历也应使用STAR法则改写每段经历，突出成果：
- **S (Situation)** - 简要背景
- **T (Task)** - 任务目标
- **A (Action)** - 采取的行动
- **R (Result)** - 量化成果

### 表达风格
- **强调成果和数据**：优先写"提升XX%"、"节省XX时间"、"服务XX用户"等量化成果
- **突出技能和工具**：明确写出使用的技术栈、工具、方法论
- **体现责任和规模**：如"负责XX模块开发"、"管理XX人团队"、"覆盖XX规模数据"

### 与定向简历的区别
- 通用简历：全面展示，不针对特定关键词
- 定向简历：融入JD关键词，强化匹配部分

**改写示例参考**[assets/examples/bullet_rewrite_examples.md](../assets/examples/bullet_rewrite_examples.md)

## 教育经历处理

与定向简历相同，参考[resume-writing.md](resume-writing.md)的"教育经历处理"章节。

**调整策略：**
- 如GPA较高（3.5+/4.0），突出显示
- 如GPA一般，可省略
- 核心课程选择最能体现候选人能力的（如技术岗列编程课程，商科岗列商业分析课程）
- 如有荣誉（奖学金、优秀学生等），列出

## 输出文件

### 文件位置
`data/<user_ID>/generic_resume_CN.md` 或 `data/<user_ID>/generic_resume_EN.md`

### 文件格式
与定向简历使用相同模板[assets/templates/resume_output_template.md](../assets/templates/resume_output_template.md)，一级标题写`# 通用-通用-<姓名>`，`求职意向`字段可删除，证件照路径写`photo.jpg`（见[resume-writing.md](resume-writing.md)的"证件照"）。区别在于：
- **通用简历**：经历板块按亮眼程度排序（大厂实习、量化成果、时间长、近期、复杂度高、有认可）
- **定向简历**：经历板块按与JD匹配度排序

填写要点：
- 个人信息和教育经历固定在前
- 后续经历板块按亮眼程度排序填充
- 技能与证书板块一般放在经历板块之后，个人优势放在最后
- 文件名中包含"generic"标识

### 补充文件
如有拿不准或候选人需要补充的内容，按模板[assets/templates/resume_notes_template.md](../assets/templates/resume_notes_template.md)写入`generic_resume_notes.md`

### 生成DOCX
同定向简历，调用`scripts/generate_resume.py`生成DOCX版本，文件名：
- `generic_resume_CN.docx` 或 `generic_resume_EN.docx`

## 使用场景

### 场景1：首次整理CV后
```
用户："我刚把我的经历整理完了，但还没想好投什么公司"
→ 生成通用简历，让用户先看看效果

用户："我想先生成一份简历看看"
→ 生成通用简历
```

### 场景2：参加招聘会/内推
```
用户："我要去参加招聘会，需要一份通用简历"
→ 生成通用简历DOCX，用户打印或发送

用户："学长要帮我内推，让我发一份简历给他"
→ 生成通用简历DOCX
```

### 场景3：快速投递
```
用户："这个岗位要求不明确，我先投一份通用简历试试"
→ 生成通用简历
```

## 与定向简历的配合

通用简历是"备用版本"，定向简历是"精准版本"：
- 通用简历生成后，候选人可以用于日常场合
- 当候选人有明确目标岗位时，基于同一份CV生成定向简历
- 定向简历会根据岗位画像重新排序和改写，比通用简历更精准

**建议用户策略：**
- 日常场合：使用通用简历
- 正式投递心仪岗位：生成定向简历
- 海投：为每个岗位生成定向简历

## 质量检查
- [ ] 所有经历来自CV，无编造事实
- [ ] 教育经历真实无误
- [ ] 经历板块按亮眼程度排序（最亮眼的在前）
- [ ] Bullet使用STAR格式，突出成果
- [ ] 文件名包含"generic"标识
