# Resume Database Skill 使用指南

## 这个Skill是什么？

Resume Database是一个**为特定岗位定制简历和面试准备**的工具，帮助大学生在海投策略中为每个岗位生成匹配度最高的简历和面试准备文档。

**核心理念：**
- 一个候选人 → 一份结构化CV → 多个岗位 → 每个岗位一份定制简历
- 不是写通用简历，而是根据JD和企业背调生成岗位定向简历
- 不是简单改关键词，而是基于岗位画像重组经历、调整表述

## 适合谁用？

- 需要海投的大学生（校招、实习）
- 有多段经历需要针对不同岗位调整呈现方式的候选人
- 需要系统化管理多个岗位投递进度的求职者

## 核心功能

### 1. 建立候选人档案
- 从零散材料（旧简历、草稿、口述）整理出结构化CV
- 一次整理，多次复用
- 支持中英文CV同步维护

### 2. 岗位深度调研
- 读取JD原文，作为最高标准
- 企业背调：定位业务线 → 深挖该业务线 → 补充公司背景
- 生成岗位画像：工作内容、核心要求、公司特定偏好、关键词清单
- **动态更新**：面试后根据面试官补充信息更新画像

### 3. 生成定制简历
- 根据岗位画像从CV中选取匹配经历
- 按匹配度排序：最匹配的放前面
- 用STAR法则或产品化表达改写bullet
- 自然融入JD关键词
- 输出Markdown和DOCX两种格式

### 4. 经历包装（独立工作流，可选）
- 当CV经历与目标岗位有gap时，可参考他人经历"包装"
- **核心原则：Fake it until you make it**
- 先按参考经历实际操作，再把真实尝试写成自己的经历
- 结果写回CV，之后所有简历复用，不需要每个岗位重新包装
- 流程见[experience-packaging.md](../workflows/experience-packaging.md)

### 5. 生成面试准备
- 按轮次生成（一面/二面/HR面）
- 每轮20个问题：10个简历深挖 + 10个有关业务
- 每轮3个反问，根据面试官类型调整
- 自我介绍（1-2分钟）
- 回答准备建议

### 6. 简历打分（独立工作流，可选）
- 只给定向简历打分，只看简历与该岗位JD的匹配度
- 输出score文档：各维度分数、扣分原因、修改建议
- 默认只打分，你要求时才自动改写
- 流程见[resume-scoring.md](../workflows/resume-scoring.md)

### 7. 投递记录追踪
- Excel表格记录投递进度
- Timeline字段追踪面试时间线
- 岗位JD以内容摘要形式记录，方便回溯

## 工作流程

本skill分为3个工作流：简历生成与投递（主流程）、经历包装、简历打分，后两者按需使用，入口见[SKILL.md](../SKILL.md)。下面是主流程。

### 首次使用

先按[setup.md](setup.md)初始化环境（Python、虚拟环境、依赖、`data/`目录），已经初始化过的仓库跳过这一步。

```
1. 建档
   你："我想投字节跳动的产品实习"
   → 系统分配user_ID，创建候选人目录

2. 整理CV
   你：提供旧简历或零散材料
   → 系统提取事实信息，生成结构化CV（cv_CN.md）

3. 提供JD
   你：粘贴JD原文或提供JD链接
   → 系统创建岗位目录，写入jd.md

4. 企业背调
   → 系统定位业务线，深度调研，生成company_background.md

5. 生成岗位画像
   → 系统结合JD、背调、面经，生成job_profile.md

6. 生成定制简历
   → 系统从CV中选取匹配经历，改写，生成简历Markdown和DOCX

7. 生成面试准备
   → 系统生成一面准备（20个问题 + 3个反问）

8. 记录投递
   → 系统更新application_tracker.xlsx
```

### 后续岗位

已有CV的情况下，只需：
```
1. 提供新岗位JD
2. 系统自动完成背调、画像、简历、面试准备
3. 记录投递
```

### 面试后更新

```
1. 面试结束后，告诉系统面试官在反问环节提供的补充信息
   （实际工作内容、技术栈、团队构成、与JD的差异等）

2. 系统更新job_profile.md，标注"最后更新"时间和原因

3. 如有二面，系统基于更新后的画像生成二面准备

4. 如需调整简历，系统基于更新后的画像重新生成简历
```

## 与传统简历工具的区别

| 传统工具 | Resume Database Skill |
|---------|---------------------|
| 一份简历投所有岗位 | 每个岗位一份定制简历 |
| 手动改关键词 | AI根据岗位画像重组经历 |
| 面试准备靠自己找面经 | 自动生成岗位定向面试准备 |
| 投递记录手动维护 | 自动记录并追踪Timeline |
| 静态简历 | 动态更新（面试后根据面试官反馈调整） |

## 重要原则

### 1. JD是最高标准
- 所有内容以JD为准
- 但面试官提供的信息 > JD（如实际技术栈与JD不同）

### 2. 教育经历绝对真实
- 学校、学历、专业、时间必须真实
- 不可包装或编造

### 3. 实习/项目经历可包装
- 遵循"Fake it until you make it"原则
- 先实际尝试，再写成自己的经历并写回CV
- 不直接复制他人描述

### 4. 岗位画像是动态的
- 初次生成基于JD + 企业背调 + 面经
- 面试后根据面试官补充信息及时更新
- 更新后重新生成简历和下一轮面试准备

### 5. 面试反问要有目的
- 一面优先问实际工作内容、技术栈（补充岗位画像）
- 二面问团队文化、发展路径
- HR面问培养机制、后续流程

## 常见场景

### 场景1：首次使用，从零开始
**你的情况：** 有一份旧简历，想投字节跳动产品岗  
**操作：** 提供旧简历 + JD → 系统整理CV → 生成定制简历和面试准备

### 场景2：已有CV，新增岗位
**你的情况：** 已投过字节，现在想投腾讯  
**操作：** 提供腾讯JD → 系统直接生成定制简历和面试准备

### 场景3：面试后更新
**你的情况：** 字节一面结束，面试官说实际用Vue而不是JD里的React  
**操作：** 告诉系统面试官的补充信息 → 系统更新job_profile.md → 生成二面准备

### 场景4：经历不够，需要包装
**你的情况：** JD要求数据分析经验，但CV里只有运营经历  
**操作：** 进入经历包装工作流，系统提供数据分析项目参考 → 你按参考实际操作 → 系统把你的真实尝试写回CV

### 场景5：给简历打分
**你的情况：** 生成了字节产品岗的简历，想知道和JD匹配度如何  
**操作：** 进入简历打分工作流，系统按JD逐项打分并给出修改建议；需要自动修改时告诉系统

### 场景6：查看投递进度
**你的情况：** 想看自己投了哪些公司，进度如何  
**操作：** 打开data/10001/application_tracker.xlsx（10001换成你的user_ID），查看进度列
