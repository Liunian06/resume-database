# DOCX生成规则

## 目标

把简历Markdown`<basename>.md`转换为DOCX`<basename>.docx`。Markdown只是脚本的输入数据，用户最终只看Word，所以脚本与`assets/templates/resume_output_template.md`必须一一对应。

## 调用方式

```bash
python scripts/generate_resume.py --input <basename>.md
```

参数：
- `--input` 必填，简历Markdown路径
- `--out-dir` 可选，输出目录，默认与输入文件同目录
- `--docx` 可选，DOCX文件名，默认与输入文件同名
- `--pdf` 可选，额外用LibreOffice导出PDF；默认不导出，用户明确要求才加

依赖：`python-docx`。

## Markdown与Word的对应关系

| Markdown | Word |
|---|---|
| `# <企业>-<岗位>-<姓名>` | 不输出，仅作文档标签 |
| `## 基本信息`的`姓名` | 顶部居中，18磅加粗 |
| `求职意向` | 姓名下一行，居中，10磅（求职意向：X） |
| `求职城市` | 再下一行，居中，10磅（求职城市：Y） |
| `手机`、`邮箱` | 再下一行，居中，10磅，用` | `连接，缺的字段跳过；手机号显示时自动在第3位和第7位后加空格（`13800000000` → `138 0000 0000`） |
| `证件照` | 头部右上角，2.2×3.1cm（略小于1寸，以免头部过高留白太多），照片右侧距正文边线0.5cm；有照片时头部用三列无边框表（左右各2.8cm、中间文字），姓名等文字仍居页面正中；没有该字段则头部不变。图片文件不存在时报错 |
| `## <板块名>` | 表格中的合并整行，11磅加粗，该单元格带1.25磅黑色下边框（表格边框，不用段落边框） |
| 教育经历的学历行 | 4列：学校、学历、专业居左，时间居右，10磅加粗。分段式：每段学历一行，该段的描述bullet合并行紧跟其下；合并式：所有学历行连续排列，总描述bullet合并行放在最后 |
| `### 名称｜职位｜时间` | 3列（前两列合并）：名称、职位居左，时间居右，10磅加粗 |
| `- ` 行 | 合并整行，一个bullet一个段落，圆点，10磅；行首`**标签：**`加粗 |

基本信息以下的全部内容在**同一张表**里：4列网格（7.3 / 2.7 / 5.0 / 4.0 cm，总宽19cm），行数随内容增加。教育经历用4列；其余板块的标题行、详细内容行合并成1个单元格，经历标题行把前两列合并成3列（10.0 / 5.0 / 4.0）。表格无边框。

## 版式（写死在脚本里）

- 字体：全文MiSans（中文、英文、数字均指定，并去掉主题字体覆盖），由用户机器已安装字体提供
- A4，页边距上下左右均为1.0cm，行距1.0，段前段后0
- 不支持自定义版式、图片、链接

## 格式校验

Markdown不符合模板时，脚本输出`ERROR: Markdown 格式错误：第N行：...`并返回1，不生成DOCX。常见原因：
- `基本信息`出现了模板之外的字段（如所在地、作品集）
- 缺少`姓名`
- `###`标题没有用全角`｜`分成三段
- 教育表头与`| 学校 | 学历 | 专业 | 时间 |`不一致
- 经历板块里有不属于`###`或`- `的行

## 覆写规则

目标DOCX已存在则直接覆盖，不备份，不做版本追踪。

## 生成后检查

- [ ] 中文无乱码，字体显示正常
- [ ] 姓名、板块标题、经历标题加粗正确
- [ ] 教育表格和经历标题的列对齐正确
- [ ] bullet缩进正确
- [ ] 内容控制在1页内（多于1页时精简低匹配经历）

## 调用时机

步骤8"生成DOCX"时调用：确认`<basename>.md`已生成 → 调用脚本 → 检查`<basename>.docx`是否生成。失败时按报错行号回改Markdown。
