# 岗位画像生成

## 目标

结合JD、企业背调和面经，生成只对这家公司这个岗位有效的画像，不套用跨公司的通用岗位模板。

**岗位画像是动态文档：** 每当用户补充面试经验、找到新的面经或互联网信息时，应及时更新画像。特别是面试官在反问环节提供的补充信息（实际技术栈、工作内容、团队构成、考核重点），优先级最高，需立即更新到画像中。

## 输入内容

### 必读
- `jd.md` - JD原文（**最高优先级**）
- `company_background.md` - 企业背调信息

### 可选读取
- 公共面经库：`data/interview_library/<company>_<position>.md`
- 个人面经：`data/<user_ID>/jobs/<company>-<position>/interview_*.md`
- 参考[interview-library-usage.md](interview-library-usage.md)了解面经读取规则

## 画像内容

### 1. 岗位工作内容（从JD提取，排首位）
- **日常工作：** JD职责部分的具体内容
- **核心产出：** 该岗位产出的交付物（如报告、代码、方案、数据看板等）
- **协作对象：** 从JD中提取协作团队/角色

### 2. 岗位核心要求（从JD提取）
- **硬性要求：** 学历、专业、技能、工具、经验年限等
- **软性要求：** 沟通能力、学习能力、团队协作等
- **加分项：** 优先考虑的背景或技能

### 3. 公司特定偏好（从企业背调和面经提取）
- 该公司在这个岗位上的特殊要求
- 面试中常考察的能力点
- 该公司的文化特点对岗位的影响

### 4. 关键词清单
- 从JD中提取的高频关键词
- 简历改写时应强化的词汇
- 分类：技能类、业务类、能力类

## 生成规则

### 优先级
参考[conflict-resolution.md](conflict-resolution.md)：
1. **面试官提供的信息** > JD原文 > 企业背调 > 面经
2. 面试官信息来自个人面经中的"面试官补充信息"板块
3. 如面试官的说法与JD有出入（如实际技术栈、工作内容），以面试官为准并在画像中标注差异
4. 首次生成画像时无面试官信息，以JD为准；面试后根据面试官补充信息更新画像

### 表述原则
- 使用JD原文的表述和用词
- 不使用"产品族"、"XX岗位通常..."的跨公司泛化表达
- 明确标注信息来源（如"JD要求"、"面经反映"）

### 避免的内容
- "所有互联网公司的数据分析岗都..." - 不要跨公司泛化
- "数据分析族的核心能力是..." - 不要使用岗位族概念
- "根据行业经验..." - 只基于JD和该公司背调

## 输出文件

### 文件位置
`data/<user_ID>/jobs/<company>-<position>/job_profile.md`

### 文件格式
从模板 [assets/templates/job_profile_template.md](../assets/templates/job_profile_template.md) 复制创建。

**填写要点：**
- "岗位工作内容"放在首位，从JD职责部分提取
- "岗位核心要求"从JD任职要求部分提取，保持原文用词
- "公司特定偏好"不写跨公司通用规律，只基于企业背调和面经
- "关键词清单"分类为技能类、业务类、能力类
- 底部标注所有信息来源

## 质量检查

- [ ] 画像内容与JD直接对应，无跨公司泛化
- [ ] 关键词清单覆盖JD中的核心词汇
- [ ] 标注了信息来源
- [ ] 如有面经，提取了公司特定偏好
- [ ] 如有面试官补充信息，已更新到画像中并标注差异

## 更新时机

画像应在以下情况下更新：
1. **用户完成面试后**：特别是面试官在反问环节提供了补充信息
2. **发现新的面经**：从公共面经库或互联网找到该公司该岗位的新面经
3. **获得内部信息**：通过内推人、校友、社交媒体等渠道获得该岗位的内部信息
4. **JD更新**：公司修改了JD内容（如技术栈、职责描述）

更新时，在画像顶部的"生成时间"下方增加"最后更新"字段，并在"信息来源"中标注新增的信息来源。
